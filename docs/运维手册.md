# 运维手册

## 日常巡检

### 每日巡检清单

```bash
# 1. 容器状态
docker compose -f /opt/server-deploy-toolkit/docker-compose.yml ps

# 2. 健康检查
python /opt/server-deploy-toolkit/health_check.py

# 3. 磁盘使用率
df -h / /var/lib/docker

# 4. 内存/CPU
free -h && uptime

# 5. 登录审计
last -n 10
```

### 设置定时巡检

```bash
# 每 5 分钟健康检查
*/5 * * * * python /opt/server-deploy-toolkit/health_check.py --json >> /var/log/health_check.log 2>&1

# 每天 8:00 巡检汇总
0 8 * * * python /opt/server-deploy-toolkit/health_check.py >> /var/log/daily_check.log 2>&1
```

## 数据库备份与恢复

### 自动备份

```bash
# 加入 crontab，每天凌晨 2 点全量备份
0 2 * * * bash /opt/server-deploy-toolkit/backup.sh >> /var/log/backup.log 2>&1
```

### 手动备份

```bash
bash /opt/server-deploy-toolkit/backup.sh          # 全量
bash /opt/server-deploy-toolkit/backup.sh --binlog # 全量 + binlog
```

### 备份恢复

```bash
# 1. 找到要恢复的备份文件
ls -lt /var/backups/mysql/*.sql.gz

# 2. 解压
gunzip /var/backups/mysql/backup_20260101_020000.sql.gz

# 3. 恢复
mysql -u root -p < /var/backups/mysql/backup_20260101_020000.sql

# 4. 验证
mysql -u root -p -e "SHOW DATABASES;"
```

## 故障处理预案

### 预案 1：MySQL 服务不可用

```bash
# 症状：网站报错 "Database connection refused"
# 排查：
docker compose logs mysql --tail=20

# 常见原因及解决：
# ① 磁盘满 → 清理日志和过期备份
df -h
docker system prune -a

# ② 内存不足 → 调低 innodb_buffer_pool_size
# 在 mysql/conf.d/my.cnf 中修改后重启
docker compose restart mysql

# ③ 启动失败 → 重建容器
docker compose down mysql
docker compose up -d mysql
```

### 预案 2：Redis 内存溢出

```bash
# 症状：Redis 连接超时、响应缓慢
# 排查：
docker compose logs redis --tail=20 | grep -i oom

# 解决：
# ① 立即释放内存
docker compose exec redis redis-cli FLUSHALL

# ② 调高 maxmemory（redis/redis.conf）
# ③ 重启恢复
docker compose restart redis
```

### 预案 3：磁盘空间满

```bash
# 排查：
df -h
du -sh /var/lib/docker/* | sort -rh | head -5

# 解决：
docker system prune -a -f            # 清理镜像
docker compose logs --tail=1         # 检查日志大小
journalctl --vacuum-size=200M        # 清理系统日志
```

### 预案 4：Docker 服务异常

```bash
# 症状：docker ps 无响应

# 解决：
sudo systemctl restart docker
docker compose -f /opt/server-deploy-toolkit/docker-compose.yml up -d
```

## 日志管理

### Docker 日志限制

```bash
# 在 /etc/docker/daemon.json 中添加日志大小限制
{
  "log-driver": "json-file",
  "log-opts": {
    "max-size": "10m",
    "max-file": "3"
  }
}

sudo systemctl reload docker
```

### 清理日志

```bash
# 清理 Docker 容器日志
echo "" > $(docker inspect --format='{{.LogPath}}' nginx)

# 清理系统日志
sudo journalctl --vacuum-size=200M
```

## 安全加固

- [ ] 定期修改密码：`passwd ops`（每季度）
- [ ] 检查 SSH 登录记录：`lastb | head -20`
- [ ] 查看恶意登录尝试：`grep "Failed password" /var/log/auth.log | tail -20`
- [ ] 更新系统补丁：`yum update -y`（CentOS）/ `apt update && apt upgrade -y`（Ubuntu）
- [ ] 检查异常进程：`ps aux --sort=-%cpu | head -10`
